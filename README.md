# daen141kk — interactive liquid glass

Персональная страница daen141kk: настоящее 3D из крупных стеклянных форм,
живой фон, пять профилей и переключатель тем. Статика без бэкенда — только HTML, CSS, JS
и предсобранные ассеты, готовые к GitHub Pages.

Опубликованная версия: <https://daen141k.github.io/daen141kkbio/>

---

## Что внутри

**Главный экран**
Асимметричная композиция без рамок и карточек: слева аватар, имя, страна и местное время
(МСК, UTC+3), крупная наборная пара `DAEN` / `141KK` (вторая строка контурная), три основных
входа и строка метаданных. Правую половину занимает шар диаметром почти в две высоты
экрана, под ним — такое же крупное кольцо; оба обрезаны краями экрана. Подсказка «scroll» с круглым ядром убрана.

**Тон: брутализм**
Оформление переведено в плоский брутальный язык: чёрный фон по умолчанию, жёсткие прямые
углы (`--r-*` сведены к нулю), вместо теней — линии в один-два пикселя, все подписи
моноширинные и капсом, кнопки и карточки при наведении инвертируются целиком (белое на
чёрном ↔ чёрное на белом). Бегущая строка инвертирована относительно страницы: в тёмной
теме это белая полоса с чёрными словами.

Поверх всего лежат плоские белые фигуры из спрайта (`#g-ring`, `#g-cross`, `#g-asterisk`,
`#g-tri`, `#g-sq`, `#g-dots`) — кольцо, крест, звёздочка, треугольник, квадрат, точки.
Они декоративные, `pointer-events: none`, часть обрезана краями секций. Японские знаки
(`ダエン`, `リンク`, `プロジェクト`, `作品`, `自己紹介`, `連絡`, `準備中`) работают как
графические марки: крупный вертикальный рельс в hero и «Связи», призрачный `作品` за
заголовком проектов, подписи в надзаголовках. Шрифт — Noto Sans JP 900, урезанный до
двадцати трёх знаков (6.9 KB), поэтому японский не зависит от системы.

Светлая тема осталась (переключатель в шапке), но по умолчанию включена тёмная:
`<html data-theme="dark">`, а скрипт в `<head>` переключает на светлую только если она
сохранена в `localStorage`.

**Проекты**
Новая секция между профилями и «О себе»: `02 Проекты`. Список — жёсткая таблица строк,
каждая строка при наведении заливается инверсией. Первый проект — `BIO` со ссылкой на живую страницу
<https://daen141k.github.io/daen141kkbio/>, тегами (three.js, HTML / CSS / JS, GitHub Pages)
и бейджем `live`; вторая строка — заглушка «Дальше / 準備中» со статусом `soon`, чтобы было
видно, что список будет пополняться. Номер секции в шапке и навигации обновлён: 01 профили,
02 проекты, 03 о себе, 04 связь.

**Цвет**
Один акцент: бирюза в трёх глубинах (`--teal`, `--teal-strong`, `--teal-soft`) на бумаге и
графите. Лайм и зелёный из прошлых версий сведены к тем же бирюзовым (`--lime` и `--green`
теперь алиасы `--teal-soft`), поэтому фон, частицы, бегущая строка, карточки профилей,
иконка и стекло живут в одной гамме, а не в трёх. Слова бегущей строки — графит, точки
между ними — бирюза; карточки профилей различаются размером и номером, а не цветом
платформы. Контраст держится на масштабе и весе, а не на разнообразии оттенков.
Лента и полоса контактов берут цвета из токенов темы (`--band`, `--band-ink`),
поэтому светлая тема светлая целиком, тёмная — тёмная целиком.

**Фон**
Сетки больше нет: остались только медленные бирюзовые цветовые поля, зерно и редкие частицы.
Никаких линий поверх контента.

**3D — крупные простые формы, разбросанные по странице**
Три композиции, по две формы в каждой, и каждая композиция — фоновый слой всей секции,
а не картинка в рамке. Остались только два примитива: шар и кольцо; «линза» — тот же шар,
сплющенный в пять раз по высоте. В один момент времени анимируется только одна
композиция — та, что занимает больше экрана.

| Где | Формы |
| --- | --- |
| Hero | шар `sphere` (s 1.45) справа, кольцо `ring` (0.95) внизу по центру, за ним по глубине |
| «О себе» | шар `sphere` (1.35) слева и линза (1.2, `form: [1, 0.2, 1]`) справа снизу |
| «Связь» | кольцо `ring` (1.25) справа, шар `sphere` (1.3) в левом нижнем углу |

Формы намеренно простые: силуэт читается сразу, блик идёт по нему одной ровной дугой,
и нет переплетений, на которых альфа-стекло выдаёт себя. Крупный объект важнее хитрого:
шар диаметром в две высоты экрана даёт ту массу стекла, ради которой всё делается, и
стоит один силуэт вместо сотни мелких деталей. На узком кадре у каждой формы есть
уменьшенный размер (`ts`), иначе она ложится прямо под текст.

Размер задан в долях кадра (`s = 1` — ровно половина высоты кадра), поэтому объект
заведомо больше канваса и обрезается его краями: видно примерно половину, как и должно
быть у фоновой скульптуры. Канвас каждой секции растянут на всю секцию (`inset: 0`,
`pointer-events: none`), так что границы кадра совпадают с границами секции и
прямоугольников не видно. На узких экранах единица пересчитывается от ширины кадра,
иначе объект вылезает за края целиком.

Материал — `MeshPhysicalMaterial`: альфа-блендинг, `ior 1.45`, `clearcoat`, студийное
окружение для отражений; `iridescence` и `dispersion` не используются.
Свет — нейтральная студия: яркие софтбоксы на средне-серой оболочке (PMREM собирается
процедурно), поэтому у стекла резкие блики и тёмные края, а не плоская заливка.

Стекло однослойное по проходам: `MeshPhysicalMaterial` с `transparent` и `opacity 0.34`,
`ior 1.45`, `clearcoat 1`, студийное окружение для отражений — и никакого `transmission`.
Настоящая рефракция в three.js стоит целого второго рендера сцены на каждый канвас в каждом
кадре; вместе с тремя сценами это и съедало кадры, из-за чего ползла бегущая строка.
Теперь сквозь объекты действительно видно страницу (канвас прозрачный, альфа-блендинг поверх
живого фона), а объём даёт вторая оболочка меша с `side: BackSide` — два блендящихся слоя
читаются как толща стекла и стоят одного лишнего draw call вместо второго прохода.

Масштаб экономии: сцена рисуется одним проходом, без MSAA, с потолком 24 fps и DPR 1.15
(крупный hero) / 1.0 (остальные). Одновременно живёт только одна скульптура — та, что
занимает больше всего экрана; остальные замирают на последнем кадре. Пока в кадре бегущая
строка, не рисуется вообще ничего: её петля должна быть идеально ровной, а скульптура в
соседней секции может подождать.

**Курсор**
Системный курсор остаётся системным: `cursor: none` нет, Pointer Lock нет, координаты
не подменяются. За указателем плавно тянется декоративное тонкое кольцо (`position: fixed`,
`pointer-events: none`, z-index 9000, интерполяция в общем rAF-цикле): на интерактивных
элементах оно увеличивается и подсвечивается тилом, при нажатии сжимается. На тач-устройствах
и при `prefers-reduced-motion` кольцо либо не создаётся, либо движется без инерции.

**Темы**
Светлая — по умолчанию (молочный фон, графитовый текст, насыщенный тил). Тёмная — отдельная
палитра (глубокий графит, светлый текст, светящийся тил), а не инверсия. Вместе с темой пересобираются палитра стекла,
свет и цвет стекла — объекты выглядят правильно в обеих темах (на тёмном фоне тело
стекла тёмное, на светлом — светлее бумаги, иначе панно исчезает). Переключатель Light/Dark
с анимированной «таблеткой», выбор сохраняется в `localStorage` (`daen141kk:theme`)
и восстанавливается до первой отрисовки; `theme-color` и `color-scheme` меняются вместе с темой.

**Профили**
Не пять одинаковых строк, а bento-раскладка: два широких блока (Telegram, GitHub) и три узких
(Steam, FunPay, guns.lol). У всех одна бирюзовая гамма, крупная иконка (56–76 px), номер,
хэндл, стрелка с микроанимацией, наклон за курсором и подсветка свечением.
Ссылки ровно те же, что и раньше:

**О себе и связь**
Секция «О себе» — крупный псевдоним, большой стеклянный шар, обрезанный левым краем, и таблица
фактов (псевдоним, страна, часовой пояс, местное время, число профилей). Секция «Связь» —
подкрашенная полоса: Telegram как основной канал, кнопка копирования ссылки, список остальных
профилей и стеклянное кольцо фоном справа. Ни биографии, ни лозунгов — только факты.

**Знак**
Новый favicon: капля с вырезанным отверстием — самостоятельный знак проекта.
Градиентная плитка тил → зелёный → лайм, белая фигура, читается на 16 px. Одна геометрия
(`tools/prepare-assets.py`) даёт весь набор: 16/32/96/192/512, `favicon.ico`, apple-touch,
maskable, `mark.svg` и `<symbol id="mark">` в обеих страницах. Аватар не менялся.

**Движение**
Одна система: `ticker.js` (единый rAF-цикл с учётом видимости вкладки), появление секций
на скролле (`up`, `fade`, `pop`, `mask`, `left/right`), посимвольный набор только у главного
заголовка, параллакс декора, магнитные кнопки, наклон карточек, прогресс прокрутки, бегущая
строка. Три характера easing (`--e-out`, `--e-soft`, `--e-spring`). При `prefers-reduced-motion`
анимации выключаются, текст виден сразу, 3D рисует один статичный кадр.

**Навигация и подсветка раздела**
Все пункты ведут на реальные `id` секций. Клик обрабатывается явно: `preventDefault`,
расчёт позиции с учётом высоты шапки, `scrollTo({behavior:'smooth'})`, обновление hash через
`history.replaceState` и переход фокуса на секцию. Это чинит старый баг, когда повторный клик
по тому же якорю («Связь») ничего не делал, и добавляет страховку: если слабое устройство
«заморило» плавную прокрутку, через 640 мс выполняется точный переход. У активного пункта
есть состояние `is-active` (залитая тилом «таблетка») и `aria-current`, у секций —
`scroll-margin-top`.

Подсветка считается по реальным прямоугольникам секций: побеждает та, что накрывает
середину экрана; если середина ни в одной — та, что занимает больше экрана; в самом низу
страницы всегда последняя секция. Клик сразу помечает свой пункт и глушит «шпиона» на 1.3 с,
пока идёт плавная прокрутка, — иначе короткая секция «Связь» не успевала дойти до середины
высокого экрана и подсветка застревала на «О себе» (это и был баг).

**Доступность**
Семантическая разметка, skip-link, ловушка фокуса и `Escape` в мобильном меню,
`aria-pressed` / `aria-expanded`, `role="status"` для копирования, видимые `:focus-visible`,
достаточный контраст, `html-validate` без ошибок.

**Производительность**
Один rAF-цикл на страницу, ленивая загрузка 3D-чанка через `requestIdleCallback`. Каждая
сцена подписана на цикл только пока она в кадре (`IntersectionObserver`) и полностью
останавливается при скрытой вкладке; стекло рисуется с потолком 40 fps, чтобы прокрутка
и бегущая строка оставались плавными; потолок опущен до 32 fps. DPR ограничен (1.15 в «слабом»
режиме).

Бегущая строка. Трек — две одинаковые половины, анимация `translate3d(0 → −50%)` linear,
целиком на своём слое. Ключевая деталь: каждая половина имеет `min-width: 100vw`
и `justify-content: space-around`, поэтому слов всегда хватает на всю ширину экрана.
Раньше половина была уже вьюпорта (1327 px при экране 1440) — у правого края на секунду
открывался пустой зазор, а потом трек прыгал на целую половину: это и читалось как рывок.
Слова внутри половины раскладываются её флексом (`display: contents` у набора), поэтому
ритм не ломается на стыке наборов; пауза по наведению убрана, чтобы лента не замирала
под курсором; при `prefers-reduced-motion` анимация выключается.

Остальное под прокруткой: `backdrop-filter` из липкой шапки убран совсем (живое размытие
над движущейся лентой — самая дорогая вещь на странице), частицы 26 штук при 15 fps и DPR 1,
параллакс больше не читает `getBoundingClientRect` в каждом кадре (замеры копятся один раз
на кадр прокрутки, в тике только интерполяция трансформа).

Первые кадры hero-сцена меряет бюджет времени (после прогрева, без учёта компиляции шейдеров):
стабильно тяжелее ~46 мс — все сцены останавливаются и показывается статичный SVG-знак;
тяжелее ~28 мс — понижается pixel ratio.
Так же поступает браузер без WebGL и устройства с одним ядром / `prefers-reduced-data`.
Принудительно включить сцену для отладки: `?3d=force`; принудительно «слабый» режим: `?3d=low`.

## Технологии

- **HTML/CSS** — без фреймворков, CSS custom properties, `color-mix()`, grid, `clip-path`.
- **JavaScript** — ES-модули, собираются esbuild.
- **Three.js 0.170** — только в 3D-чанке: `MeshPhysicalMaterial` (альфа-стекло, clearcoat,
  две оболочки на объект), `PMREMGenerator` с процедурной студийной картой окружения,
  три независимых сцены на одной странице.
- **Pillow** — генерация иконок, `mark.svg` и карточки OG.
- Хостинг — GitHub Pages, без сервера и внешних API.

## Локальный запуск

```bash
git clone https://github.com/daen141k/daen141kkbio.git
cd daen141kkbio

npm install          # esbuild + three (нужны только для сборки)
npm run build        # пересобрать assets/js/app.js и assets/js/hero3d.js
npm run serve        # http://localhost:8080
```

`npm run watch` — пересборка при изменении `src/js/*`.
`tools/serve.py` отдаёт файлы с `Cache-Control: no-store`, поэтому после пересборки
достаточно обычной перезагрузки страницы — браузер не показывает старый бандл.
Готовые файлы уже лежат в `assets/js/`, поэтому для просмотра достаточно `npm run serve`
(или любого статического сервера): открывать `index.html` через `file://` нельзя —
ES-модули требуют http.

Ассеты: `python3 tools/prepare-assets.py` (нужен Pillow). Ключ `--keep-avatar` пересобирает
иконки, `mark.svg` и OG-карточку, не трогая производные аватара.

## Публикация на GitHub Pages

1. `git add -A && git commit -m "…" && git push origin main`
2. В репозитории: **Settings → Pages → Build and deployment → Source: Deploy from a branch**,
   ветка `main`, папка `/ (root)`.
3. Через минуту сайт будет на <https://daen141k.github.io/daen141kkbio/>.
   Файл `.nojekyll` уже в корне — он отключает обработку Jekyll и сохраняет служебные папки.

Никаких переменных окружения, ключей и серверных функций проекту не нужно.

## QA

Проверялось в Chromium (Playwright) и вручную:

- **Ширины** 320 / 390 / 768 / 1024 / 1440 / 1920 — `scrollWidth` равен ширине вьюпорта,
  горизонтальной прокрутки нет, элементы не выходят за экран.
- **3D-слои** — канвасы растянуты на свои секции и имеют `pointer-events: none`; кнопка
  в hero и все четыре ссылки в контактах остаются кликабельными (`elementFromPoint`).
